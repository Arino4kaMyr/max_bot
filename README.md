# Доступный досуг — чат-бот в MAX

Подбирает события в Казани под конкретные потребности человека в доступной среде
и объясняет по каждому событию, что подходит, что с оговоркой, а чего нет.

Трек «Досуг и развлечения», хакатон Минобрнауки × MAX.
Бот: **@t616_hakaton_max_bot**

---

## Назначение

Афиши не знают про доступность, а карты доступности не знают про события. Человек,
который передвигается на коляске, идёт с детской коляской или которому тяжело даются
лестницы, вынужден звонить на площадку перед каждым выходом — и слышать «у нас всё
доступно» от сотрудника, который не знает, что это значит.

Бот закрывает этот разрыв: доступность привязана к событию, а не к площадке, и у
каждого факта видно происхождение, дату проверки и число подтверждений.

Полное описание задачи и решения — в
[спецификации](docs/superpowers/specs/2026-09-29-accessible-leisure-bot-design.md).

## Основной пользовательский сценарий

1. `/start` → «Подобрать, куда сходить»
2. Выбрать, что важно: коляска, лестницы, детская коляска, временное ограничение,
   зрение, слух, сопровождающий. Можно несколько; есть отдельная ветка «Идём компанией».
3. Выбрать период: сегодня / на выходных / на неделе. При желании — фильтры по
   категории и бесплатным событиям.
4. Получить карточки событий с разбором доступности по пунктам.
5. «Я пойду» — после события бот задаст два вопроса и обновит данные для следующих.

Вторая ветка — «Помочь с данными о доступности»: любой посетитель отвечает на
5–6 вопросов без терминов и может приложить фото входа.

## Запуск

```bash
cp .env.example .env      # вписать BOT_TOKEN
docker compose up --build
```

Одна команда поднимает PostgreSQL и приложение. Схема создаётся автоматически,
справочник площадок Казани заливается при первом старте, афиша подтягивается
из KudaGo сразу после запуска и далее раз в час.

### Переменные окружения

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `BOT_TOKEN` | токен чат-бота MAX | — обязательна |
| `DATABASE_URL` | подключение к PostgreSQL | `postgres://app:app@db:5432/accessible` |
| `CITY_SLUG` | город пилота (slug KudaGo) | `kzn` |
| `CITY_TZ` | часовой пояс города | `Europe/Moscow` |
| `SYNC_CRON` | расписание синхронизации афиши | `0 * * * *` |
| `DIGEST_CRON` | проактивная сводка | `0 12 * * 4` (четверг, 12:00) |

Секреты в репозитории не хранятся: `.env` в `.gitignore`, `.env.example` — без значений.

### Порты

Приложение не слушает входящие соединения — обновления получает через long polling,
поэтому внешние порты не нужны. PostgreSQL слушает 5432 внутри сети compose.

### Локальный запуск без Docker

```bash
npm ci
createdb accessible                 # или любой доступный PostgreSQL
export DATABASE_URL=postgres://localhost:5432/accessible
export BOT_TOKEN=...
npm run dev
```

## Проверка решения

```bash
npm test          # 37 юнит-тестов: матчинг, доверие, периоды, парсинг афиши
npm run typecheck
DATABASE_URL=... npx tsx scripts/smoke.ts
```

`scripts/smoke.ts` проходит весь путь целиком: миграция → сид → загрузка событий из
KudaGo → подбор под профиль «коляска» → печать карточек → подбор для компании.
Ожидаемый результат — непустые группы вердиктов и карточки вида:

```
🖼 Выставка «Обратная сторона Луны»
📍 галерея современного искусства, ул. Карла Маркса, д. 57
📅 Идёт сейчас, можно прийти в любой день · от 250 до 500 рублей

✅ Вход без ступеней — вход на уровне тротуара
✅ Доступный туалет
✅ Лифт на все этажи — на все выставочные этажи
...
Демонстрационные данные — требуют проверки на месте
```

### Остановка и повторный запуск

```bash
docker compose down        # остановить, данные сохраняются в томе pgdata
docker compose up          # запустить снова, состояние диалогов не теряется
docker compose down -v     # остановить и стереть данные
```

Состояние диалога хранится в базе, поэтому перезапуск посреди онбординга не
сбрасывает прогресс.

## Архитектура

```
bot/        клиент MAX: сцены, клавиатуры, рендер карточек
   ↓
services/   сценарии: подбор, вклад, верификация, время
   ↓
domain/     словарь признаков, профиль → требования, вердикты, доверие   ← ядро
   ↓
data/       репозитории, PostgreSQL
sync/       импорт афиши из KudaGo по расписанию
```

`domain/` и `services/` ничего не знают про MAX — бот является одним из клиентов.
Когда появится мини-приложение, оно подключится к тем же сервисам, и логику подбора
переписывать не придётся. Ядро не зависит от базы и сети, поэтому покрыто
юнит-тестами целиком.

Собственный API на проверку не заявляется.

### Ключевые решения

**Доступность — это набор фактов, а не флаг.** Минимальная единица данных —
факт о признаке площадки (`entrance_step_free`, `wc_accessible`, `lift`, …) со
значением, источником, датой и счётчиками подтверждений. Из этого выводятся свежесть,
доверие, верификация и текст карточки.

**Событие наследует признаки площадки.** Разметил одну площадку — покрыл все её
события. Переопределения на уровне события задаются вручную (экскурсия с
тифлокомментированием в месте, где его обычно нет).

**«Нет данных» — отдельный статус, а не «недоступно».** Смешать их значило бы
отсечь места, которые в действительности подходят.

**Одиночный отчёт не даёт зелёный вердикт.** Факт от единственного анонимного
посетителя показывается с оговоркой, но статус «подходит» требует двух согласных
отчётов либо проверки командой. Цена ошибки несимметрична.

## Данные и интеграции

| Данные | Источник | Статус |
|---|---|---|
| События Казани | публичное API [KudaGo](https://docs.kudago.com/api/) | реальная интеграция |
| Реквизиты и координаты площадок | публичное API KudaGo | реальные данные |
| Признаки доступности 15 площадок | `seed/venues-kzn.json` | **демонстрационные данные** |
| Признаки от посетителей | пользователи бота | краудсорсинг, с уровнем доверия |

> **Про демонстрационные данные.** Признаки доступности в `seed/venues-kzn.json`
> подобраны по типу и характеру зданий и **не проверены на месте**. Бот честно
> подписывает их прямо в карточке: «Демонстрационные данные — требуют проверки на
> месте», и такие факты не выдаются за проверенные. Перед пилотным запуском каждое
> значение проверяется очно или подтверждается площадкой, после чего в файле
> меняется источник на `manual` или `partner`.

Уровни доверия, которые видит пользователь:

| Подпись в карточке | Когда |
|---|---|
| Проверено командой | проверка наша или партнёрской организации |
| По информации площадки | заявлено площадкой, не проверено на месте |
| Демонстрационные данные — требуют проверки | предзаполненный набор |
| Подтвердили N посетителей | два и более согласных отчёта |
| Со слов одного посетителя — уточните на месте | единственный отчёт |
| Данные расходятся, нужна проверка | появилось опровержение |

## Сертификаты

`certs/max-ru-ca.pem` — публичные сертификаты НУЦ Минцифры России (корневой и
промежуточный). API платформы MAX (`platform-api2.max.ru`) работает на них, а в
наборе доверенных сертификатов Node.js их нет: без этого файла подключение падает с
`UNABLE_TO_GET_ISSUER_CERT_LOCALLY`. Сертификаты публичные, приватных ключей не
содержат и подключаются только к этому приложению через `NODE_EXTRA_CA_CERTS`, а не
к системному хранилищу. Источник —
[gu-st.ru](https://gu-st.ru/content/Other/doc/russian_trusted_root_ca.cer).

## Известные ограничения

- Один город в данных (Казань). Переключение города — параметр `CITY_SLUG`, а не
  изменение кода; для нового города нужен свой файл `seed/venues-<slug>.json`.
- KudaGo по Казани отдаёт около 60 актуальных событий, значительная часть — постоянные
  экспозиции. Они показываются как «идёт сейчас».
- Признаки доступности в сиде демонстрационные (см. выше).
- Мини-приложение и карта не реализованы: архитектура к ним готова, но это следующий
  шаг после пилота.
- Фото входа хранятся ссылкой на файл в MAX; при удалении файла в мессенджере ссылка
  перестанет открываться.
- Проактивная сводка отправляется только тем, у кого заполнен профиль и не выключены
  напоминания.
